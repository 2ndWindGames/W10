# 개봉노트 구현 명세

기준: W09의 세 번째 앱에서 참조한 공통 기획서 `Mobile_Apps_Planning_with_UI_v1.0.pptx`. 원본을 W10 `Documentation/Reference`에 보관했다. 공통 규칙은 3~4쪽, 네 번째 앱은 28~34쪽, 시안은 29쪽이다. W09 자체에는 PPT가 없으므로 W08에 보관된 동일 기획서를 사용했다.

시안의 분류(식품·생활용품·기타)와 메모(200자), 보관함 검색을 함께 제공한다. 사진이 없으면 자체 벡터 제품 아이콘이 표시된다. 보관함은 20개씩 페이지로 보여주며 검색/페이지 이동 때 이전 사진 텍스처를 해제한다. 첫 실행에는 사용자가 입력하지 않은 기록을 만들지 않는다.

## 저장 및 알림 구조

Android 내부 저장소 `Context.getFilesDir()/openednote/opened-note.json`, 사진은 같은 디렉터리의 `photos/`. 사진의 상대 파일명은 GUID 형식만 허용한다. 앱은 네트워크 권한과 자동 OS 백업을 사용하지 않는다.

`OpenedStore`가 단일 기준 자료다. 네이티브 알림 수신기도 예약 정보만 믿지 않고 저장 완료된 JSON을 다시 읽는다. 제품 보관·삭제, 알림 날짜 변경 직후 프로세스가 종료되어도 오래된 예약이 잘못 전달되지 않게 상태와 알림 버전을 확인한다. 알림을 한 번 보낸 버전은 재예약하지 않는다. 날짜·시간대 변경, 재부팅, 앱 업데이트 때 미래 예약만 복원한다.

정확한 알람 특수 권한을 요구하지 않는 `setAndAllowWhileIdle` 1회 알림을 사용한다. 지정 시각보다 일찍 울리지 않으며 절전 등 OS 정책에 따라 지연될 수 있다. 날짜를 지난 지연 알림은 발송하지 않는다. Android에서 앱을 강제 종료한 경우 앱을 다시 열기 전까지 OS가 예약/수신을 막을 수 있다.

사진 선택은 API 33 이상에서 플랫폼 Photo Picker, 이전 버전에서 Storage Access Framework를 사용한다. 크기 25MB 및 픽셀 수 제한 후 작업 스레드에서 축소·회전·JPEG 재인코딩하고, 파일 저장 완료 이후 초안에 반영한다. 기기에서 HEIF 등 해당 형식을 해독할 수 없는 경우 다른 사진을 선택하거나 사진 없이 저장할 수 있다.

## 출시 범위

PPT 3쪽과 51쪽에서 결제는 별도 단계이며 34쪽의 3,900원은 검증 가설이다. 1.0.0은 사용 중 15개를 제공하는 무료 버전으로 구현한다. 구매·복원 기능, 바코드, OCR, 섭취 안전 판단, 서버 동기화는 출시 기능에 포함하지 않는다.

Android API 26 이상 / target API 36 / Unity 6000.3.23f1 / IL2CPP ARM64 / OpenGLES3 / 세로 화면. Android 16의 큰 화면·창 크기 변경에서 스크롤과 UI 너비를 조정한다.
